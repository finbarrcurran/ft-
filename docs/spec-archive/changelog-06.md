# FT spec archive — change log, part 06

Full, unedited change-log entries of the FT master spec, oldest first (this file only ever grows at the end; existing text is never edited — a correction goes in a new entry). Map of every version and pass to its file: INDEX.md.

>
> **Overhaul:** 2026-10-19 (ninety-third pass) — **SC-52 P2: full transcript store and search (v1.88.0).** Migration 0057 adds `video_transcripts` (video id, source, channel, title, url, date, duration, method, the captions text with its `[NNNs]` markers, a sha, fetched-at) and an FTS5 external-content index `video_transcripts_fts` kept in step by triggers. FTS5 is available in the Go driver (modernc sqlite, tested before the migration was written). Every complete package on disk is stored by the daily sweep (and by `ft transcripts sync`), whether or not it has been digested, so the corpus can be searched without any LLM extraction; an unchanged re-sync writes nothing and a changed transcript replaces the old text in the index. Search: `GET /api/transcripts/search?q=&source=&from=&to=&limit=` and the new read-only connector tool `search_transcripts` (inside the SC-41 read-only scope; no write path), also `ft transcripts search|sync|stats`. A query is a word, several words that must all occur, or a quoted phrase; the text is turned into quoted FTS5 terms, so operators in a query never reach MATCH. Results carry the video, date, a snippet with the match marked, and a timestamped link at the nearest marker before the hit. The corpus is public video content, so demo mode does not change it. No LLM spend. On the live data (33 packages: 25 Cowen, 8 Jordi, 959 KB) a search for 'accumulation' returns the two Cowen videos that use the word, with the right dates; 'hedge fund' returns five Jordi videos including the 2026-10-18 one. A SQLite backup carries the table and its index (tested with VACUUM INTO). Tests: right video and second for a phrase, multi-word, source and date filters, no match, injection-safe queries, idempotent store and update, backup, sweep and sync, the endpoint's validation. Not included: transcripts for videos that have no package yet (that is the backfill, P3). Reference updated: §3, §5, §11, §12. Supersedes v1.87.0.
>
> **Overhaul:** 2026-10-19 (ninety-fourth pass) — **SC-52 P4: capital flows from the statements (v1.89.0).** The statement importer now also reads the Account Activity sheet and stores dated capital flows in the new table `etoro_capital_flows` (migration 0058): deposits, transfers to trading, withdrawals, transfers to eToro Money, the cancelled-request reversal, and the deposit/withdrawal conversion fees. A row is keyed by a hash of its timestamp, type, details, amount and occurrence, so re-imports and overlapping statements add nothing twice. Each statement is reconciled against its own Account Summary (inflows = Deposits + Transfer to Trading; withdrawals; transfers to eToro Money net of reversals; FX fees to within 5 cents because eToro rounds per row) and the result is kept in `etoro_statement_periods.flows_summary_json`; mismatches, non-zero Credits / Internal Transfer / Transfer in / Transfer out lines and flow-like activity types FT does not recognise are warnings. On the five real statements the three main lines reconcile to the cent (the 2025 and 2025-07 → 2026-10 statements differ from eToro's fee total by $0.02 of rounding). Stored: 93 rows, 2025-08-31 to 2026-06-01. **The gap question:** the last flow is 2026-06-01 while the statements run to 2026-10-09; the Activity sheet from 2026-06-02 to 2026-10-09 contains only position opens/closes, dividends, interest payments and one adjustment, so nothing was missed: no deposit, withdrawal or transfer happened in that window. Flows after the last statement are unknown, not zero, and the snapshot says so. Surfaces: `GET /api/etoro/performance` carries `capitalFlows`; the Performance tab shows a 'Capital flows (statements)' line; the weekly snapshot's 'of which' notes now quote the flows recorded in the period (or 'none recorded', or 'not known after <statement end>') instead of the blanket sentence that flows are not recorded. Manual fallback: `POST /api/etoro/capital-flows` (day, direction in/out, amount, note), `GET` to list, `DELETE /{id}` for manual rows only; no manual-entry form was built. This path is separate from the break-glass holdings reconcile and its open hardening: no holdings are touched, and full-history statements were parsed only on a copy of the database, not applied to the live one. Tests: parse and exact reconciliation of a realistic synthetic statement, identical same-second rows, stable keys, mismatch and unknown-type warnings, rounding tolerance, idempotent store with an overlapping statement, summary by year, manual add/delete, snapshot notes for no statement / stale statement / flows / quiet period, and the Performance tab line in a real browser test. Reference updated: §3, §5, §11. Supersedes v1.88.0.

> **Overhaul:** 2026-10-19 (ninety-fifth pass) — **SC-52 P5: Bargo replaces Capitol Trades for real (v1.90.0).** Fin's decision (2026-10-19): Bargo is the Congress source, Capitol Trades is retired. The spec had recorded the cron as removed on 2026-10-11, but `/etc/cron.d/ft-capitol-trades` was still installed on Jarvis and kept running at 23:05 UTC every night (failing on a page timeout; the last good scrape was 2026-08-14); it was deleted on 2026-10-19 and `ops/scrapers/ft-capitol-trades.cron` was removed from the repo. The script stays until Fin says delete. The Signals tab now shows Bargo's freshness under the Congress section (last good sync, newest disclosure, newest trade, House and Senate member counts, and a note when the latest run failed), from `GET /api/signals` field `congressFeed`; the connectivity monitor's `bargo` check already guards the feed. Coverage parity, measured: Bargo has delivered 848 trades since 2026-07-13 (778 House from 41 members, 70 Senate from 9 members, newest disclosure 2026-10-15) against the 285 legacy Capitol Trades rows from 2024-08-20 to 2026-08-05 (274 House, 11 Senate); Bargo rows carry no party (legacy rows did) and its history starts 2026-07-13, so older history is only the legacy file. The Congress signal events already come from Bargo (source ids 'bargo:…'). Named-individual tracking (Trump 278-T) never came from Capitol Trades: it uses the OGE path, which has stored one annual statement and zero 278-T transaction events, so it is not affected by this change (and has produced nothing yet). Farside: the cron log path fix holds (log in ~curran/logs, last run 2026-10-19 00:25, newest ETF-flow row 2026-10-16), and the monitor's farside check alerts when the scraper or the source goes quiet. Tests: the feed status through the real handler (sync log, newest dates, legacy rows counted as history, a failed latest run). Reference updated: §4, §5. Supersedes v1.89.0.

> **Overhaul:** 2026-10-19 (ninety-sixth pass) — **SC-52 P6: housekeeping, flag rather than delete (v1.91.0).** (1) Migration 0059 adds `regime_history.seed_excluded`; the weekly snapshot's history seeding skips flagged rows, while the regime history view and the audit trail are untouched (nothing is deleted). The migration flags the four 2026-05-16 rows (Jordi and Cowen, notes 'smoke test' and 'reset'); that is what put a fictional Cowen 'defensive' into the first snapshots. The ten June 2026 Jordi rows (ids 5-14: 05-31 and 06-01 changes, six flips within two minutes on 06-04, two eight seconds apart on 06-09) are NOT flagged: Fin must first confirm they were not real changes, then `ft regime-history flag --ids 5,...` does it. New CLI `ft regime-history list|flag`. (2) NewsAPI stays as a disabled fallback and the planned 2026-10-27 removal is cancelled: the market-news handler now treats anything other than an explicit `meta.market_news_source = newsapi` as RSS (before, an unset value, as on a rebuilt database, meant NewsAPI), the startup missing-key alert asks for `NEWSAPI_API_KEY` only when the fallback is selected, and the spec documents it as the fallback. Provider counters show one NewsAPI call on 2026-10-12 and 2026-10-13 and none since. Tests: a flagged row does not seed while the row remains; the news source defaults to RSS for empty, unknown and mixed-case settings and selects NewsAPI only for 'newsapi'. Reference updated: §3, §8, §11. Supersedes v1.90.0.
