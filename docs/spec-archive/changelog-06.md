# FT spec archive — change log, part 06

Full, unedited change-log entries of the FT master spec, oldest first (this file only ever grows at the end; existing text is never edited — a correction goes in a new entry). Map of every version and pass to its file: INDEX.md.

>
> **Overhaul:** 2026-10-19 (ninety-third pass) — **SC-52 P2: full transcript store and search (v1.88.0).** Migration 0057 adds `video_transcripts` (video id, source, channel, title, url, date, duration, method, the captions text with its `[NNNs]` markers, a sha, fetched-at) and an FTS5 external-content index `video_transcripts_fts` kept in step by triggers. FTS5 is available in the Go driver (modernc sqlite, tested before the migration was written). Every complete package on disk is stored by the daily sweep (and by `ft transcripts sync`), whether or not it has been digested, so the corpus can be searched without any LLM extraction; an unchanged re-sync writes nothing and a changed transcript replaces the old text in the index. Search: `GET /api/transcripts/search?q=&source=&from=&to=&limit=` and the new read-only connector tool `search_transcripts` (inside the SC-41 read-only scope; no write path), also `ft transcripts search|sync|stats`. A query is a word, several words that must all occur, or a quoted phrase; the text is turned into quoted FTS5 terms, so operators in a query never reach MATCH. Results carry the video, date, a snippet with the match marked, and a timestamped link at the nearest marker before the hit. The corpus is public video content, so demo mode does not change it. No LLM spend. On the live data (33 packages: 25 Cowen, 8 Jordi, 959 KB) a search for 'accumulation' returns the two Cowen videos that use the word, with the right dates; 'hedge fund' returns five Jordi videos including the 2026-10-18 one. A SQLite backup carries the table and its index (tested with VACUUM INTO). Tests: right video and second for a phrase, multi-word, source and date filters, no match, injection-safe queries, idempotent store and update, backup, sweep and sync, the endpoint's validation. Not included: transcripts for videos that have no package yet (that is the backfill, P3). Reference updated: §3, §5, §11, §12. Supersedes v1.87.0.

> **Overhaul:** 2026-10-19 (ninety-fourth pass) — **SC-52 P4: capital flows from the statements (v1.89.0).** The statement importer now also reads the Account Activity sheet and stores dated capital flows in the new table `etoro_capital_flows` (migration 0058): deposits, transfers to trading, withdrawals, transfers to eToro Money, the cancelled-request reversal, and the deposit/withdrawal conversion fees. A row is keyed by a hash of its timestamp, type, details, amount and occurrence, so re-imports and overlapping statements add nothing twice. Each statement is reconciled against its own Account Summary (inflows = Deposits + Transfer to Trading; withdrawals; transfers to eToro Money net of reversals; FX fees to within 5 cents because eToro rounds per row) and the result is kept in `etoro_statement_periods.flows_summary_json`; mismatches, non-zero Credits / Internal Transfer / Transfer in / Transfer out lines and flow-like activity types FT does not recognise are warnings. On the five real statements the three main lines reconcile to the cent (the 2025 and 2025-07 → 2026-10 statements differ from eToro's fee total by $0.02 of rounding). Stored: 93 rows, 2025-08-31 to 2026-06-01. **The gap question:** the last flow is 2026-06-01 while the statements run to 2026-10-09; the Activity sheet from 2026-06-02 to 2026-10-09 contains only position opens/closes, dividends, interest payments and one adjustment, so nothing was missed: no deposit, withdrawal or transfer happened in that window. Flows after the last statement are unknown, not zero, and the snapshot says so. Surfaces: `GET /api/etoro/performance` carries `capitalFlows`; the Performance tab shows a 'Capital flows (statements)' line; the weekly snapshot's 'of which' notes now quote the flows recorded in the period (or 'none recorded', or 'not known after <statement end>') instead of the blanket sentence that flows are not recorded. Manual fallback: `POST /api/etoro/capital-flows` (day, direction in/out, amount, note), `GET` to list, `DELETE /{id}` for manual rows only; no manual-entry form was built. This path is separate from the break-glass holdings reconcile and its open hardening: no holdings are touched, and full-history statements were parsed only on a copy of the database, not applied to the live one. Tests: parse and exact reconciliation of a realistic synthetic statement, identical same-second rows, stable keys, mismatch and unknown-type warnings, rounding tolerance, idempotent store with an overlapping statement, summary by year, manual add/delete, snapshot notes for no statement / stale statement / flows / quiet period, and the Performance tab line in a real browser test. Reference updated: §3, §5, §11. Supersedes v1.88.0.

> **Overhaul:** 2026-10-19 (ninety-fifth pass) — **SC-52 P5: Bargo replaces Capitol Trades for real (v1.90.0).** Fin's decision (2026-10-19): Bargo is the Congress source, Capitol Trades is retired. The spec had recorded the cron as removed on 2026-10-11, but `/etc/cron.d/ft-capitol-trades` was still installed on Jarvis and kept running at 23:05 UTC every night (failing on a page timeout; the last good scrape was 2026-08-14); it was deleted on 2026-10-19 and `ops/scrapers/ft-capitol-trades.cron` was removed from the repo. The script stays until Fin says delete. The Signals tab now shows Bargo's freshness under the Congress section (last good sync, newest disclosure, newest trade, House and Senate member counts, and a note when the latest run failed), from `GET /api/signals` field `congressFeed`; the connectivity monitor's `bargo` check already guards the feed. Coverage parity, measured: Bargo has delivered 848 trades since 2026-07-13 (778 House from 41 members, 70 Senate from 9 members, newest disclosure 2026-10-15) against the 285 legacy Capitol Trades rows from 2024-08-20 to 2026-08-05 (274 House, 11 Senate); Bargo rows carry no party (legacy rows did) and its history starts 2026-07-13, so older history is only the legacy file. The Congress signal events already come from Bargo (source ids 'bargo:…'). Named-individual tracking (Trump 278-T) never came from Capitol Trades: it uses the OGE path, which has stored one annual statement and zero 278-T transaction events, so it is not affected by this change (and has produced nothing yet). Farside: the cron log path fix holds (log in ~curran/logs, last run 2026-10-19 00:25, newest ETF-flow row 2026-10-16), and the monitor's farside check alerts when the scraper or the source goes quiet. Tests: the feed status through the real handler (sync log, newest dates, legacy rows counted as history, a failed latest run). Reference updated: §4, §5. Supersedes v1.89.0.

> **Overhaul:** 2026-10-19 (ninety-sixth pass) — **SC-52 P6: housekeeping, flag rather than delete (v1.91.0).** (1) Migration 0059 adds `regime_history.seed_excluded`; the weekly snapshot's history seeding skips flagged rows, while the regime history view and the audit trail are untouched (nothing is deleted). The migration flags the four 2026-05-16 rows (Jordi and Cowen, notes 'smoke test' and 'reset'); that is what put a fictional Cowen 'defensive' into the first snapshots. The ten June 2026 Jordi rows (ids 5-14: 05-31 and 06-01 changes, five flips within about two and a half minutes on 06-04, two eight seconds apart on 06-09) are NOT flagged: Fin must first confirm they were not real changes, then `ft regime-history flag --ids 5,...` does it. New CLI `ft regime-history list|flag`. (2) NewsAPI stays as a disabled fallback and the planned 2026-10-27 removal is cancelled: the market-news handler now treats anything other than an explicit `meta.market_news_source = newsapi` as RSS (before, an unset value, as on a rebuilt database, meant NewsAPI), the startup missing-key alert asks for `NEWSAPI_API_KEY` only when the fallback is selected, and the spec documents it as the fallback. Provider counters show one NewsAPI call on 2026-10-12 and 2026-10-13 and none since. Tests: a flagged row does not seed while the row remains; the news source defaults to RSS for empty, unknown and mixed-case settings and selects NewsAPI only for 'newsapi'. Reference updated: §3, §8, §11. Supersedes v1.90.0.

> **Overhaul:** 2026-10-27 (ninety-seventh pass) — **SC-52 P0.1 (revised regime prompt, entity fix) and P1 (login regime proposal) (v1.92.0).** Fin and ai (2026-10-27): the first extraction made Jordi Shifting in 8 of 8 videos because Shifting was defined by named dated catalysts, which he names in every video. P0.1 redefines the states by the posture he recommends for adding or holding equity risk (Stable: hold and/or add; Shifting: be cautious about ADDING, not a broad drawdown; Defensive: cut risk or expects a broad material drawdown; Unclassified: no posture), says that naming catalysts, events, dates or volatility does not by itself make a view Shifting, keeps his crypto views out of the regime (they go to `cross_asset_tilt`), and defines the accumulation stance (accumulating / waiting / holding / reducing / unstated; 'holding' is new). `ExtractionVersion` is now 3. Re-running the 9 Jordi digests (about $0.27 through the governor, plus one $0.03 preview): Stable 6, Shifting 2 (2026-09-27 and 2026-10-18, the hedge-fund deleveraging video, with a 'waiting' stance), one with no kept state (2026-09-06; a re-run of it gave Stable/high, so the loss was quote grounding on that run); accumulation stance accumulating 7, waiting 1, holding 1. The 10-18 digest matches Fin's reading (uncertainty until the hedge-fund unwind and the midterms; wait for stability). Fix: caption HTML entities (`&amp;`, `&gt;&gt;`, `&#39;`) are unescaped before the text reaches the model, the stored transcripts and the search snippets (the 16 stored transcripts that still contain `&amp;` are corrected by `ft transcripts sync`, which rewrites a changed transcript and its index entry). P1: `GET /api/regime/proposal` and `POST /api/regime/proposal/{approve,set,dismiss}`, and a card on login (Jordi only) that shows the narrative, the proposed state with the confidence prominent, the evidence passage (labelled 'closest passage' when snapped) with title, date and a timestamped link, the current state with set date and age, FT's macro suggestion beside it (disagreement stated, neither preferred), a consequence preview from the live alert logic (effective regime, alert margin, entry-zone alerts, affected watchlist tickers), stance and tilt as context, and the catalysts. It shows for a new unhandled proposal or a regime past the 14-day stale flag; a manual set after the digest supersedes the proposal; dismiss snoozes until the next digest; the corner x hides it for the session. Approve applies the digest's own state (the client cannot name another), 'set a different state' is its own call; both write through the manual regime path with source `video-suggestion` in the preferences and a regime_history row (source `manual`, the table's CHECK) whose note and inputs name the digest, quote, match and prior state. No LLM call at login, never auto-applied, hidden in demo mode. Tests: prompt definitions and no-steering, entity unescape, the 'holding' stance, proposal show/hide (new, dismissed, next digest, superseded, stale with and without a digest, version below 3), consequence preview against the live alert functions and the watchlist, approve/set/dismiss with audit and refusal of a stale digest id, demo mode, and a real-Chromium test of the card (16 checks). Also: the snapshot freshness test now uses the real clock for the stale flag. Reference updated: §5, §12. Supersedes v1.91.0.

> **Overhaul:** 2026-10-27 (ninety-eighth pass) — **SC-52 P0.2 (cited evidence) and P3 tooling (transcript-only backfill, extract-on-request) (v1.93.0).** ai (2026-10-27): the model's evidence quote was often a stitched paraphrase, so FT now has the model cite the supporting transcript segment and supplies the words itself. The extraction asks for `evidence_ref` {start_sec, end_sec} in place of a copied quote (also `ref` for the cross-asset tilt and the accumulation stance); FT resolves it to the transcript text (verbatim by construction, at most 60 words, cut at a sentence end, a reference wider than 45 s clamped, a start snapped to the nearest marker within 20 s). The marker spacing in the compact transcript is now 15 s (was 30 s), which makes citations and `?t=` links finer; stored transcripts are rewritten by the next sweep. `proposed_quote_match` gains `cited`; the model's own quote (`exact`) and the closest-passage snap (`nearest`) remain as fallbacks. State determination is unchanged. `ExtractionVersion` is 4. P0.1 wording fix: holding without adding is Stable unless he tells people to wait for stability, a pullback or an event before adding; 'hold what you have' is removed from Shifting. Test on the 2026-09-06 and 2026-10-11 videos: the first attempt had the model citing windows 75 s wide and every reference was refused (a too-tight rule on my side: now clamped, and the prompt asks for at most 30 s); on the second attempt both were kept as `cited` with sensible passages (09-06: Stable/high on 'Do you really want to focus on the bond thing with what I just showed you? We've been going higher.'; 10-11: Stable/high on 'The digital economy is where the future is. It's what you want to be long…'). Re-extracting 2026-08-30 and 2026-09-27 gave Stable/medium and Shifting/medium, both `cited`; the 10-18 check waits for the P3 window's raised cap. P3 tooling: the Jarvis-side `video_digest.py` is now in the repo (`ops/video_digest/`) with a range backfill (`--from/--to`, `--no-frames`, `--transcripts-only`, `--captions-only`, `--max-videos`, `--sleep`, a metadata cache, and a hard stop on a YouTube rate limit). A package written with `--transcripts-only` carries `meta.extract = false`; the daily sweep stores and indexes its transcript but never extracts it (this rule had to be live before any such package exists, because the previous sweep would have sent every Cowen package to the LLM). New `ft video-digest-extract` digests packages without a digest on request, newest or oldest first, flagship-only if asked, never twice, within `--max-cost` (stopping one video short of it), and `--daily-cap` lifts `llm_budget_daily_usd` for the run and always restores it (also on Ctrl-C or SIGTERM); the monthly cap is untouched. Tests: the P0.1 wording, citation resolution (snap, clamp, cap at a sentence, refusals), the fallback chain cited, exact, nearest, dropped, tilt and stance references, the sweep skipping transcript-only packages while storing their transcripts, newest-first flagship-only extraction one at a time without duplicates, and the ceiling. Reference updated: §5, §11. Supersedes v1.92.0.

> **Overhaul:** 2026-10-27 (ninety-ninth pass) — **SC-52: majority vote for the newest Jordi digest (v1.94.0).** ai (2026-10-27): the regime state of a single extraction can flip between runs, so the newest Jordi digest, the one behind the login card, is extracted three times and the majority state is kept. The sweep does this automatically for a newly ingested Jordi video that is the newest Jordi digest (the stored run plus two unstored runs, about $0.06 extra); a split (2 of 3, or three different states, tie going to the more cautious state) sets confidence to low and the card shows '2 OF 3 RUNS' (a unanimous result shows '3 OF 3 RUNS'). The kept proposal is the representative run's state, quote, narrative and match. Migration 0060 adds `video_digests.proposal_runs` and `proposal_agree`. Not applied to the backfill or `ft video-digest-extract`. `ft video-digest-vote` runs it by hand; `Preview` now respects the governor's output-token cap like the real ingest. Tests: majority (2 of 3, confidence low, narrative and quote taken from the winning run), unanimous (3 of 3, no change), a three-way split going to the more cautious state with 1 of 3, one run is not a vote, and the sweep without voting makes a single call. Reference updated: §3, §5. Supersedes v1.93.0.

> **Overhaul:** 2026-10-28 (hundredth pass) — **CLI fixes: flags after the query, no stray database (v1.94.1).** `ft transcripts search halving --source cowen` read `--source cowen` as part of the query (Go's flag package stops at the first non-flag word) and returned nothing; flags are now accepted before or after the query (the connector path was never affected). Every CLI command except serve and seed now refuses to run when the database file named by FT_DB_PATH (default ./data/ft.db) does not exist, instead of silently creating an empty one (the 2026-10-28 stray ./data/ft.db); FT_ALLOW_NEW_DB=1 overrides. Tests: flag order and multi-word queries. Reference updated: §10. Supersedes v1.94.0.
