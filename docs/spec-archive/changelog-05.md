> **Overhaul:** 2026-10-11 (seventy-fourth pass) — **Statement-fallback fixes, scrapers restored, older audit gap documented (v1.77.3).** Off Fin's go-ahead and ai's findings from Fin's screenshots of 2026-10-10 (reproduced offline against a copy of the live DB first). **SC-17 statement fallback (`etoro_reconcile.go`):** (1) crypto is scoped to wallet `eToro` — the preview had proposed closing 13 Binance/Ledger/MetaMask/Phantom holdings; the same rule SC-44 already had; applied crypto adds are now tagged wallet `eToro` (they were created with none, so they could never match again); (2) FT has no units column, so the preview now uses the **live SC-42 units** (`etoro_holdings_effective`) as 'FT units' and as what a drift proposal applies, and derives units (invested ÷ avg_open_price) **only for USD listings** — for GBp/JPY/EUR listings the division mixed a USD cost with a local-currency price and invented drift (RR.L +7,387%, 4063.T +15,624%); when FT already matches the live data a differing statement is shown in sync with a partial-close note and never applied (statements cannot see partial closes: RHM.DE); the statement's USD average price is no longer written into a non-USD listing's `avg_open_price` (it previously could be); (3) a statement ticker without an exchange suffix (`SU`) matches the single FT holding with that base (`SU.PA`) with needs_confirm and a note, instead of an add plus a closure; (4) the fallback's apply handler now writes `holdings_audit` rows (create/update/soft_delete, reason_code `etoro_statement_reconcile`, no trade snapshot). **Master-file import:** an eToro account statement uploaded there (it used to parse to an empty diff and look accepted) is detected (`etoro.LooksLikeStatement`: Account Summary + Closed Positions + Account Activity sheets) and rejected with a pointer to Performance → Upload statement / Stocks → Reconcile with eToro statement. > **Overhaul:** 2026-10-11 (seventy-fifth pass) — **SC-47: Bargo Congress feed, raw trade history and the connectivity monitor (v1.78.0).** Off Fin's go-ahead ("build Bargo and the monitor together"). **Congress feed:** `internal/bargo` replaces the blocked Capitol Trades scraper. It calls Bargo's free Congress API (`https://www.bargo.ai/free-apis/congress/v1/trades`, Bearer key from `FT_BARGO_API_KEY`, never in the URL) in 7-day transaction-date slices, newest-first pages of 250 rows (100 keyless). The first run backfills the 92-day window Bargo serves; later runs re-read the last 14 days (disclosures lag trades by up to ~45 days) and Sundays re-read 60. Every row is upserted into the new **`congress_trades_raw`** table (migration 0049; unfiltered, unique on a hash `source_key` of member, chamber, ticker, type, both dates and amount band, since Bargo exposes no record id — two genuinely identical lines would collapse). The table is the history FT keeps after rows age out of Bargo's 3-month window. The legacy `trades.json` (last written 2026-08-14) is imported into it once (`source='capitol_trades'`). `signals.RefreshCongress` (the 23:10 UTC job and the Signals tab's ⟳ Congress button) imports the legacy file, syncs Bargo, then `IngestCongressFromRaw` turns recent Bargo rows with a ticker into tiered `signal_events` through the existing `ingestCongressBatch` (idempotent). A 429 after at least one good request is a **partial** run (cursor saved so the next run resumes), not a failure; 401/403 and other errors fail the run and are recorded in `provider_health` (`bargo`) and `bargo_sync_runs`. The Signals tab footer carries the attribution Bargo's terms require. The Capitol Trades cron is retired (`ops/scrapers/install.sh` now removes `/etc/cron.d/ft-capitol-trades`). **Connectivity monitor (`internal/monitor`):** every 10 minutes (first run 5 minutes after start) it reads each watched source's last success and compares it with the silence that source is allowed: Yahoo, CoinGecko, Finnhub (12 h); Twelve Data, Frankfurter (36 h); Alternative.me (48 h); CNN Fear & Greed, NewsAPI, crypto RSS (72 h) from `provider_health`; Bargo (36 h) from `bargo_sync_runs`; eToro sync (3 h) from `etoro_sync_runs`; the Farside file (50 h) and the newest nightly DB backup (30 h) by file time. CryptoCompare (broken since May) is optional: shown, never alerts. It is a freshness monitor, not a ping, because Finnhub and Twelve Data fail most calls on their free tiers yet still succeed several times a day. State is in `monitor_state`, history in `monitor_events`; it sends one Telegram message when a source goes stale, a reminder every 24 h while it stays stale, and one on recovery; sources already stale at first sight are folded into one 'monitor is on' message. Delivery is direct to Telegram using `FT_TELEGRAM_BOT_TOKEN` / `FT_TELEGRAM_CHAT_ID` (plain text, no URLs in errors); with them unset events are stored as undelivered and Diagnostics says so. Settings → Diagnostics shows each source's status, last success and allowed silence, plus the last 15 events. **Found on the way:** FT's `/etc/ft/env` had no Telegram variables, so the LLM-budget Telegram alerts (`internal/llm/alerts.go`) were also going nowhere; Twelve Data reports 1,872 credits used against an 800/day limit and Finnhub is returning 429s (both far over budget, long-standing); CNN Fear & Greed and NewsAPI last succeeded 2026-09-18 and crypto RSS 2026-09-29. Tests: Bargo upsert/idempotence/history-survives, auth failure, quota-partial and cursor, key never in the URL; monitor down/reminder/recovery, first-run consolidation, optional sources silent, undelivered recorded; raw-to-signals ingest. Reference updated: §2, §3, §4, §5, §8, §9, §12. Supersedes v1.77.3.
