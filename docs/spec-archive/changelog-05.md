> **Overhaul:** 2026-10-11 (seventy-fifth pass) — **SC-47: Bargo Congress feed, raw trade history and the connectivity monitor (v1.78.0).** Off Fin's go-ahead ("build Bargo and the monitor together"). **Congress feed:** `internal/bargo` replaces the blocked Capitol Trades scraper. It calls Bargo's free Congress API (`https://www.bargo.ai/free-apis/congress/v1/trades`, Bearer key from `FT_BARGO_API_KEY`, never in the URL) in 7-day transaction-date slices, newest-first pages of 250 rows (100 keyless). The first run backfills the 92-day window Bargo serves; later runs re-read the last 14 days (disclosures lag trades by up to ~45 days) and Sundays re-read 60. Every row is upserted into the new **`congress_trades_raw`** table (migration 0049; unfiltered, unique on a hash `source_key` of member, chamber, ticker, type, both dates and amount band, since Bargo exposes no record id — two genuinely identical lines would collapse). The table is the history FT keeps after rows age out of Bargo's 3-month window. The legacy `trades.json` (last written 2026-08-14) is imported into it once (`source='capitol_trades'`). `signals.RefreshCongress` (the 23:10 UTC job and the Signals tab's ⟳ Congress button) imports the legacy file, syncs Bargo, then `IngestCongressFromRaw` turns recent Bargo rows with a ticker into tiered `signal_events` through the existing `ingestCongressBatch` (idempotent). A 429 after at least one good request is a **partial** run (cursor saved so the next run resumes), not a failure; 401/403 and other errors fail the run and are recorded in `provider_health` (`bargo`) and `bargo_sync_runs`. The Signals tab footer carries the attribution Bargo's terms require. The Capitol Trades cron is retired (`ops/scrapers/install.sh` now removes `/etc/cron.d/ft-capitol-trades`). **Connectivity monitor (`internal/monitor`):** every 10 minutes (first run 5 minutes after start) it reads each watched source's last success and compares it with the silence that source is allowed: Yahoo, CoinGecko, Finnhub (12 h); Twelve Data, Frankfurter (36 h); Alternative.me (48 h); CNN Fear & Greed, NewsAPI, crypto RSS (72 h) from `provider_health`; Bargo (36 h) from `bargo_sync_runs`; eToro sync (3 h) from `etoro_sync_runs`; the Farside file (50 h) and the newest nightly DB backup (30 h) by file time. CryptoCompare (broken since May) is optional: shown, never alerts. It is a freshness monitor, not a ping, because Finnhub and Twelve Data fail most calls on their free tiers yet still succeed several times a day. State is in `monitor_state`, history in `monitor_events`; it sends one Telegram message when a source goes stale, a reminder every 24 h while it stays stale, and one on recovery; sources already stale at first sight are folded into one 'monitor is on' message. Delivery is direct to Telegram using `FT_TELEGRAM_BOT_TOKEN` / `FT_TELEGRAM_CHAT_ID` (plain text, no URLs in errors); with them unset events are stored as undelivered and Diagnostics says so. Settings → Diagnostics shows each source's status, last success and allowed silence, plus the last 15 events. **Found on the way:** FT's `/etc/ft/env` had no Telegram variables, so the LLM-budget Telegram alerts (`internal/llm/alerts.go`) were also going nowhere; Twelve Data reports 1,872 credits used against an 800/day limit and Finnhub is returning 429s (both far over budget, long-standing); CNN Fear & Greed and NewsAPI last succeeded 2026-09-18 and crypto RSS 2026-09-29. Tests: Bargo upsert/idempotence/history-survives, auth failure, quota-partial and cursor, key never in the URL; monitor down/reminder/recovery, first-run consolidation, optional sources silent, undelivered recorded; raw-to-signals ingest. Reference updated: §2, §3, §4, §5, §8, §9, §12. Supersedes v1.77.3.

> **Overhaul:** 2026-10-12 (seventy-seventh pass) — **SC-41b: OAuth 2.1 for the claude.ai MCP connector, login rate limiting, small fixes (v1.79.0).** Off ai's work order E. Fin found that claude.ai's Add-custom-connector dialog has only Name and URL (no request-headers field), so the static bearer of SC-41 (v1.72.1) cannot work. New `internal/oauth` is a single-user OAuth 2.1 authorization server inside FT (migration 0050: `oauth_clients`, `oauth_codes`, `oauth_tokens`, hashes only): RFC 9728 protected-resource metadata (`resource` = `https://ft.curranhouse.dev/mcp`), RFC 8414 server metadata (authorization_code + refresh_token, S256 only, public clients), RFC 7591 registration limited to `https://claude.ai/api/mcp/auth_callback` and loopback redirects (50-client cap, 10/h/IP), `/authorize` (Fin approves with his FT password; consent page states read-only access and the redirect host; frame-ancestors none), `/token` (form-encoded, PKCE S256, resource-bound, 1 h access tokens, rotating 30-day refresh tokens, code replay or refresh-token reuse revokes the family and sends a Telegram alert). `requireReadToken` takes a second path for `ft_oat_` tokens; the 401 now carries `WWW-Authenticate: Bearer resource_metadata=…, scope="read"`; static `ft_mcp_` tokens are unchanged; only the six read-only tools exist (no write path). `/.well-known/*` and `/register` no longer fall through to the SPA page (they returned HTML 200). **Pre-check finding:** FT's login had no rate limit, lockout, failure log or alert and no second factor (argon2id, 64 MiB per guess, so parallel guesses also cost memory). Now `POST /api/auth/login` and `/authorize` share a limiter (5 failures per IP per 15 min, 30 overall per hour, 429 with Retry-After, no permanent lock) with failure logging and a Telegram alert on the first lockout. CLI: `ft token revoke`, `ft oauth status|revoke-all|revoke-client|create-client [--secret]`; Diagnostics shows OAuth counts; `ft help` now lists every command and the new env vars. Tests (`internal/oauth`): discovery JSON and S256 advert, no HTML on well-known, registration rules and rate limit, full flow, wrong PKCE verifier, code replay revokes tokens, rotation, refresh reuse revokes the family and alerts, expiry (access 1 h, code 60 s), foreign resource, JSON token request rejected, login limiter and deny, loopback port matching. Not verifiable here: claude.ai's own behaviour (Fin tests the connector; v1.72.1 showed docs do not capture everything). Cloudflare WAF rule is manual (no API token). Reference updated: §3, §5, §11. Supersedes v1.78.1.
